SENTINEL AI
Your money has a bodyguard.

An autonomous agent on iPhone + AWS that investigates risky activity case by case — then protects the account when the evidence says so.

Stack

What each service does in Sentinel

AWSAPI Gateway + Lambda host the FastAPI agent. Secrets Manager holds keys. EventBridge schedules suspend. OpenAITool-calling investigator: pulls transactions, GPS matches, security events, then writes a structured conclusion. ClickHouseStores live iPhone GPS and runs geospatial / time-window queries the agent uses as evidence. MongoDBPersists incidents, policies, and bank account state (including freezes) across requests. ElevenLabsGenerates the AI fraud-hotline voice after a high-risk freeze escalation. iPhone / SwiftUICore Location GPS, Face ID for freeze/unfreeze, alerts, and Demo Lab scenario triggers.

Case 1

Restaurant charge

Should Verify — Zuni Café

A delayed restaurant bill posts days later. Sentinel checks whether your phone was near the restaurant around purchase time.

  • Charge linked to Zuni Café
  • In-person card purchase
  • GPS history shows you were nearby
Outcome: Verified — no panic, no freeze
Services used iPhone GPS AWS API ClickHouse OpenAI MongoDB
Case 2

Restaurant charge

Needs Review — Cotogna

Same delayed-bill pattern, but ClickHouse finds no GPS points close to Cotogna in the purchase window.

  • Missing location is not treated as proof of fraud
  • Customer can tap “This is fine” or freeze with Face ID
  • Shows up alongside Verified cases in one inbox
Outcome: Needs review — ask the human
Services used iPhone GPS ClickHouse OpenAI MongoDB AWS
Case 3

International online purchase

Phone in SF. Merchant labeled Colombia.

Online orders often show a foreign merchant location even when you shop from home. Sentinel does not auto-freeze on the label alone.

  • GPS puts the phone in San Francisco
  • Channel is card-not-present / online
  • No takeover cluster (new device + MFA + cash-out)
Outcome: Needs review — cut false freezes
Services used ClickHouse GPS OpenAI investigation MongoDB incident AWS
Case 4

Risky Colombia card use

Card-present abroad raises the stakes.

Unlike the online case, an in-person foreign card pattern is treated as higher risk and can escalate into account protection when bundled with other signals.

  • Agent pulls card channel + security context
  • Policy may authorize a freeze
  • Surfaces as Account protected in Alerts
Outcome: Account protected when risk clusters
Services used OpenAI MongoDB bank state AWS Lambda iPhone alerts
Case 5 · Part A

Stolen phone / account takeover

Investigate. Then freeze.

New device, MFA change, failed sign-ins, new transfer recipient, risky transfer — OpenAI investigates with tools; policy freezes the account.

  • Customer status: Account protected
  • Findings listed in plain language
  • Unfreeze requires Face ID
Outcome: Account frozen
Services used OpenAI tools MongoDB AWS iPhone Face ID Notifications
Case 5 · Part B

Prove the freeze

Attacker transfer: blocked.

Immediately after takeover, attempt a $25 transfer to attacker-cashout@evil.example.

  • Bank enforces the protective restriction
  • Status: rejected / restricted
  • Account status remains Frozen
Outcome: Transfer blocked — freeze verified
Services used AWS API MongoDB bank state iPhone Demo Lab Urgent notification
Case 5 · Part C

Fraud hotline escalation

ElevenLabs speaks for the agent.

After a freeze, Sentinel can escalate with an AI voice — the message an assistant would deliver to a fraud hotline: who it is, what happened, keep the freeze.

  • Live ElevenLabs text-to-speech
  • Face ID before generating the voice
  • Discloses it is an AI assistant
Outcome: Hotline voice ready
Services used ElevenLabs AWS iPhone Face ID
